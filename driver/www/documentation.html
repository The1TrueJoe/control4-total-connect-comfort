Total Connect Comfort Thermostat

Control4 driver for Honeywell Total Connect Comfort thermostats, using the same unofficial portal API as pyhtcc.

Setup

  1. Add the driver to a room in Composer Pro.
  2. Set Username and Password to your mytotalconnectcomfort.com credentials.
  3. Leave Device ID blank to auto-select the first thermostat on the account, or set it explicitly (visible in the portal URL as portal/Device/Control/<id>) if the account has more than one thermostat.
  4. Set Temperature Scale to match the unit your TCC account displays in.

Notes

  • Auto HVAC mode is not offered for setting: the portal API has no documented write value for it, so only Off/Heat/Cool are exposed as settable modes. If the thermostat is physically in an Auto state, it is reported as whichever of Heat/Cool is currently active.
  • Outdoor temperature is not reported; the portal only exposes it via scraping an HTML control page, which this driver does not do.
  • Use the Refresh Now command to poll immediately, and Log Out to force a fresh login on the next poll (useful after changing the account password).

Polling and rate limits

mytotalconnectcomfort.com has no official API, and there are recurring forum/GitHub reports (pyhtcc, homebridge-tcc, and others) of accounts or IPs getting rate-limited or temporarily banned from polling it too often. This driver is deliberately conservative about request volume:

  • Poll Interval (seconds) defaults to 300 (5 minutes) and cannot be set below 60. A thermostat's temperature and setpoints don't change fast enough to need tighter polling, and Refresh Now is always available for an on-demand check.
  • Changing a setpoint or mode from the Control4 UI does not trigger an immediate poll. Instead it schedules a refresh a few seconds later, and that timer is pushed back on every further change — so dragging a setpoint slider costs one refresh request when you stop, not one per step.
  • The session (login) is cached for the life of the driver and only refreshed if the portal reports the session as expired, rather than logging in on every request.
  • If the portal rejects the Username/Password, or reports too many login attempts, the driver stops trying to log in automatically — see below.

If Username/Password is wrong: auth lockout protection

The portal will temporarily lock an account out (with a cool-down timer) after enough failed login attempts. To make sure this driver can never be the cause of that, the very first time a login attempt comes back as a rejected credential or a "too many attempts" response, the driver stops making any further login requests entirely — the automatic poll timer will not retry, no matter how long it runs. Connection Status will show Auth Blocked and Last Error will explain why.

To try again, either:

  • Correct Username or Password — changing either clears the block and makes one fresh attempt, or
  • Run the Refresh Now command — this is the one action that deliberately clears the block and retries, for when you believe the credentials are right and any portal cool-down has passed.

Don't repeatedly hit Refresh Now while unsure whether the credentials are correct — each click is a real login attempt against the portal, same as retyping a password on the website.
